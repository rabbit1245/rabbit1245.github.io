# K볼 · PLAYER CAREER

선수 한 명을 만들고 훈련, 경기, 이적, 은퇴까지 직접 이어가는 한국어 축구 커리어 게임입니다. React와 TypeScript로 화면과 시뮬레이션 엔진을 분리했으며, 경기 계산은 Web Worker에서 실행합니다.

## 2.1 개선안 반영

- **화면:** Pretendard를 파일에 포함했습니다. 본문·능력치명 17px, 주요 수치 20~24px를 사용하고 라커룸·능력치·훈련을 좌우 공간에 배치했습니다. 능력치 설명창을 없애고 값과 변화량을 바로 보여줍니다. 긴 기록은 선택한 시즌과 페이지로 전환합니다.
- **훈련·계산:** 생성 마지막 단계에서 실제 시작 수치를 확인하고 계획을 확정합니다. 이후 오프시즌에 한 번 확정하며 시즌 중에는 조회합니다. 훈련·출전 경험·발달·부상 손실과 시즌 사이 노화를 구분해 저장하고 보고합니다.
- **일정·계약:** 국대는 리그 달력 중 실제 게임 경기일에 진행해 이후 클럽의 체력·부상·선발에 반영합니다. 첫 계약·재계약·이적의 이전/새 조건과 날짜, 시즌 시작 몸값을 보존합니다.
- **호환:** 기존 v1·배포된 v2 저장의 해시와 과거 기록을 그대로 검증합니다. 없던 과거 성장 원인이나 계약 이력은 만들지 않고 새 진행부터 추적합니다.
- **규정 확인:** 2026/27 공식 규정 전체 확인은 완료하지 못했습니다. 현재 공식 사이트가 이 환경의 네트워크에서 403으로 차단됩니다. 실제 명칭과 게임 모형을 구분하고 평가한 게임 기간·모형 버전을 보관합니다. [규칙과 미확인 범위](docs/RULES.md)를 참고하세요.

Pretendard는 [SIL Open Font License](public/FONT-LICENSE.txt)로 배포하며 사이트·단일 HTML·ZIP에 라이선스를 포함합니다.

## 실행

Node.js 20.19 이상이 필요합니다.

```sh
npm ci
npm run dev
```

프로덕션 빌드를 실행하려면 다음 명령을 사용합니다.

```sh
npm run build
npm run preview
```

GitHub Pages에는 `dist/`를 배포합니다. 저장소 Settings → Pages의 Source를 GitHub Actions로 선택한 뒤, `Publish Kball to GitHub Pages` 워크플로를 수동 실행할 수 있습니다. 다운로드 파일을 보관하는 `kball-playable` 브랜치와 메인 사이트 배포는 별개입니다.

## 파일로 바로 플레이

[다운로드 브랜치의 Kball.zip](https://github.com/rabbit1245/rabbit1245.github.io/raw/refs/heads/kball-playable/Kball.zip?download=1)을 내려받아 압축을 풀고 `Kball.html`을 최신 Chrome 또는 Edge로 엽니다. 게임 코드, 선수 명단과 구단 로고가 파일 안에 포함되어 있습니다. 사용자에게 Node.js나 Python 설치는 필요하지 않습니다. 저장 데이터는 브라우저에 보관되므로 파일 이름·위치 또는 브라우저를 바꾸기 전에 JSON으로 내보내세요.

개발자가 이 파일을 다시 생성하려면 Node.js와 Python 3가 설치된 환경에서 다음 명령을 사용합니다.

```sh
npm run build:playable
```

생성물은 `play/Kball.html`과 `play/Kball.zip`이며 Git에서 제외됩니다. 단일 파일은 외부 자산 요청 없이 Blob Worker, 경기 진행, 저장, 파일 백업과 오프라인 진행을 검증합니다. 이 클라우드의 관리형 브라우저는 `file://` 주소 열기를 차단하므로 여기서의 자동 검증은 동일한 HTML을 HTTP로 전달해 수행합니다.

## 플레이

1. 새 커리어에서 선수 정보, 포지션, 플레이스타일, 재능, 시작 구단과 첫 훈련 계획을 선택합니다.
2. **라커룸**에서 준비를 마치고 전반기, 중간 정비 후 후반기를 진행합니다. 선택한 훈련은 시즌 중 고정되며 다음 오프시즌에 한 번 확정합니다. 순위는 내 팀 주변과 승강 경계부터 보여주고 전체 표는 페이지로 확인합니다.
3. **선수**에서 각 능력치의 시작값·현재값·변화, 실제 경기 행동과 관련 지표, 시장가치·계약·주급을 확인합니다. 몸값 변동은 계약 주급을 자동으로 바꾸지 않습니다.
4. **커리어**에서 통합·클럽·국대 세 줄을 선택해 같은 자리의 역할별 9개 지표를 바꿔 봅니다. 기간·대회·소속·연령 단계를 선택하고 시즌 이력, 수상, 주장 임기와 이적 기록을 확인합니다.
5. 이적시장과 재계약 제안은 라커룸에서 검토합니다. 응답이 필요한 제안만 진행을 멈추며 일반 MOM·부상·국대 소식은 결과와 함께 짧게 표시합니다. 저장·불러오기·새 커리어와 연출 줄이기는 상단 공통 메뉴에 있습니다.

진행은 각 선수의 별도 IndexedDB 슬롯에 자동 저장합니다. 저장 관리에서 수동 저장, 이전 정상본 복구, JSON 내보내기·가져오기를 제공합니다. 브라우저의 사이트 데이터를 삭제하면 슬롯도 지워지므로 중요한 커리어는 파일로 내보내세요. 가져오기는 기존 슬롯을 덮어쓰지 않습니다. 처음 온라인에서 빌드를 연 뒤 오프라인 캐시가 준비되면 같은 주소에서 다시 접속해 플레이할 수 있습니다. 서버나 로그인, 외부 API는 필요하지 않습니다.

반시즌은 내부에서 개별 경기를 순서대로 계산하고, 이미 확정된 결과를 짧은 장면으로 보여줍니다. 연출 건너뛰기·움직임 줄이기는 경기 결과나 기록을 바꾸지 않습니다. 현역 때 보는 통산 기록과 은퇴 후 기록도 같은 경기 원장을 합산합니다.

## 경기와 이어지는 시스템

- 필드 20개·GK 10개 능력치를 실제 패스, 기회 창출, 슈팅, 돌파, 경합, 저지와 선방 판정에 사용합니다. 특정 능력치 하나만 바꾸고 상대·출전·다른 능력치를 고정한 반복 경기로 효과 방향을 검증합니다.
- 필드·골키퍼 각각 9개 핵심 지표와 공통 출전·선발·시간·평점·MOM을 제공합니다. 성공률은 합산한 성공과 시도로 다시 계산하고 90분당 기록을 함께 보여줍니다. 골키퍼의 득점·도움도 보존합니다.
- 913개 구단의 선수단·연령·부상·전력·선수층·재정과 세계 경기 기록을 유지합니다. 다음 시즌의 성장·노화·은퇴·대체 영입은 선수단과 전력에 실제 반영되며 승강은 참가 리그·상대·일정·수입·영입 예산을 바꿉니다.
- 유소년은 별도의 U19 개발 경기와 순위를 사용합니다. 성인 팀은 별도 경기로 성적과 승강을 결정합니다. 실제로 보관된 어린 선수와 명시된 가상 아카데미 선수가 U19 명단을 구성하며, U19 기록으로 성인 리그 개인상이나 발롱도르를 수상하지 않습니다.
- 국대는 국적·연령·포지션 경쟁·출전·평점·부상을 보고 발탁합니다. 예선·본선·대륙대회·친선 경기의 실제 결과가 기록, 피로, 명성과 수상 평가에 반영됩니다. U20과 성인 대표 경력을 구별합니다.
- 시장가치의 현재·이전·최고 값과 이력을 보존합니다. 계약에서 결정한 주급, 구단 간 이적료, 선수의 급여·보너스 수입을 따로 계산합니다. 제안은 구단 예산과 급여 여력, 현재 계약, 기대 역할을 반영합니다.
- 클럽·국대 주장과 부주장은 근속·리더십·출전·신뢰·나이·성과로 선정하고 임시 경기 주장과 구별합니다. 임명 시점과 주장으로 출전한 경기 수를 커리어에 남깁니다.
- 실제 상의 명칭·기관·기준을 관리하고 같은 범위의 경쟁자 실제 기록으로 선정합니다. 득점·도움·무실점상은 각 지표를 비교합니다. 발롱도르 30인과 연도별 순위, 포지션별 FIFPRO 월드 11을 보존합니다. 선정 투표와 MOM 평가는 게임 모형이며 실제 공식 수상 결과라는 뜻은 아닙니다. 구단 최다 득점은 일반 기록으로 표시하고 가상의 성장 트로피는 만들지 않습니다.

## 데이터와 모델의 범위

- 기존 2024/FC25 자료를 바탕으로 한 14개국, 913개 구단, 43개 리그 단계 및 복수 그룹을 분리한 50개 진행 그룹을 사용합니다. 게임 세계의 시작 연도는 2026년이며, 실제 2026/27 선수 명단이라는 뜻은 아닙니다.
- 원본 선수 중 구단에 매칭된 실명 선수 4,282명을 보존하고, 부족한 선수단을 이름에 `(가상)`을 표시한 선수로 보완했습니다. 미매칭 선수를 임의로 실제 구단에 배정하지 않습니다.
- 정규리그는 게임용 홈·원정 2회전으로 통일합니다. 국가별 리그 달력, 폐쇄형 리그, 일부 승강 예외를 구분하지만 실제 2026 규정·플레이오프·라이선스·리저브팀 자격을 전부 재현하거나 검증한 모델은 아닙니다. K2↔K3와 네덜란드 2↔3부는 자동 연결하지 않으며 미국 대회 사이에도 자동 승강하지 않습니다. 일본 2026 특별대회와 추춘제 전환은 정상 7월 시작 시즌으로 단순화합니다. 각 규정 화면에 모델 설명과 공식 기관 참고 링크가 있습니다.
- 국대 대회 명칭과 주기를 사용하지만 경기 형식은 예선 3개국 조 상위 2팀, 본선 4강·결승으로 축약합니다. 실제 국가별 예선 형식과 개최 일정을 전부 재현하지 않습니다. 명단이 부족한 국가·연령대도 가상 선수를 명시해 보완합니다.
- 국내 컵·클럽 대륙 대항전, 임대·등록 제한 전체는 구현 범위에 포함되지 않습니다. 존재하지 않는 대회 결과로 우승이나 수상을 만들지 않습니다.
- 16개 포지션, 7개 재능 등급과 포지션별 10개 플레이스타일을 제공합니다.
- 기존 CAREER24는 `legacy.html`에 보존합니다. 기존 localStorage와 새 K볼 슬롯은 서로 덮어쓰지 않으며, 기존 시즌 합계를 새 경기 원장으로 위조해 가져오지 않습니다.

이전 K볼 저장은 원래 해시를 먼저 확인한 뒤 불러옵니다. 첫 진행 명령에서 새 시스템을 초기화하며 기존 기록을 보존합니다. 과거에 수집하지 않은 세부 행동이나 NPC 기록은 만들지 않습니다. 이전·신규 경기 기록이 섞인 범위의 역할 지표에는 상세 기록이 있는 경기만 따로 집계하고 기록 범위를 표시합니다. JSON 저장 파일 한도는 128MB입니다.

## 검증

```sh
npm test                 # 엔진·능력치 민감도·세계/국대·수상·계약·저장 검증 및 30시즌 검사
npm run typecheck
npm run test:legacy      # 기존 턴 전환 테스트
npm run build
npx playwright install chromium
npm run preview          # 별도 터미널에서 유지
npm run test:e2e
node tests/v55-browser.test.mjs
```

브라우저 검증은 기본적으로 4173번 포트의 빌드를 사용합니다. `KBALL_TEST_URL`과 `CAREER24_TEST_URL`로 주소를 지정할 수 있습니다. 이미 설치한 Chromium을 사용하려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`을 지정합니다.

30시즌 검사는 세계의 모든 리그 경기를 실제 계산하므로 수 분 걸릴 수 있습니다. 단일 파일도 `KBALL_TEST_URL=http://127.0.0.1:<포트>/Kball.html`로 같은 브라우저 검증을 수행할 수 있습니다. 장기 검사에서 생성한 `test-results/long-career-30-seasons.json`은 `node tests/kball-large-save.test.mjs`로 실제 브라우저의 대용량 가져오기·저장·재접속까지 확인할 수 있습니다. 빠른 반복 검사에는 `KBALL_SKIP_LONG_TEST=1 npm test`를 사용하고, 배포 전에는 30시즌 검사도 실행합니다.

2.1 개선안의 화면·계산·장기 저장 검증 결과와 남은 범위는 [검증 기록](docs/VALIDATION.md)에 정리했습니다.
