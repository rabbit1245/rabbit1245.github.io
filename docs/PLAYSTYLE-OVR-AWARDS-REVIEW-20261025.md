# K볼 수정본 충돌·구현 가능성 검토

검토일: 2026-10-25. 대상: 미배포 `2.7.4-dev.1` 작업 트리. 첨부 문서: `K볼_플레이스타일_OVR_수상_낭만_통합개선안_수정본.txt`.

사용자가 선택한 범위는 **우선 충돌·구현 가능성 검토**다. 선수 수준표는 **수정본의 새 0~120 기준**을 향후 설계 기준으로 채택한다. 이번 검토에서는 게임 실행 코드·저장 파일·배포본을 수정하지 않았다. 앞서 완료한 국대·수상·클럽 성장·은퇴 기본 정보 개선은 미배포 상태로 보존한다.

## 결론

전체 방향은 구현 가능하다. 다만 훈련 UI 추가와 숫자 상한 변경만으로 완료할 수 있는 범위는 아니다. **실제 성장 경로, 경기 판정, 저장 검증, 평가용 OVR의 의미를 함께 맞추는 변경**이 필요하다. 기존 시뮬레이션·대회·기록 기능을 줄일 이유는 없다.

우선 해결할 설계 문제는 다음과 같다.

1. 현재 잠재력은 최대 100이고, OVR이 잠재력에 도달하면 훈련·경험 성장이 멈춘다. 상한 해제만으로는 110 성장이나 OVR 120이 가능해지지 않는다.
2. 현재 경기 판정은 세부 능력치를 100으로 잘라 사용한다. 표시만 120으로 확장하면 초과 성장의 경기 효과가 사라진다.
3. 수정본의 예시 산식은 핵심 5개가 110이어도 나머지 능력치가 충분히 높아야 120에 도달한다. 실제 훈련 경로 검증이 별도로 필요하다.
4. 현재 수상 모형은 OVR을 직접 사용하지 않는다. 새 능력 20점·성과 50점·팀 30점 방식은 평가식의 명시적 변경이다.
5. 낭만 가점에 필요한 과거 근거 일부는 현재 저장 구조에 없다. 새 시점부터 작은 증거 요약을 보존하고, 없는 과거는 미적용해야 한다.

- 현재 상태뿐 아니라 시즌 시작·끝 능력치, 성장 보고서, 수동 노화 기록, 경기 참여자, 선수단 사본·주장 평가의 관련 OVR도 범위와 일관성 검증 대상이다. 모든 `100`을 `120`으로 치환하면 체력·확률·리더십 등 별개 범위까지 훼손된다.
- 접이식 UI는 `TrainingPanel` 하단에 추가 가능하다. 작은 보조 글씨는 현재 한글명을 기준으로 연결하고 기존 흰색·연두 포인트·가독성 원칙을 유지한다.

## OVR 산식과 실제 120 도달 가능성

수정본의 산식은 다음처럼 구분해서 다룰 수 있다.

```text
기본값 = Σ 기존 포지션·전술 가중치 × min(실제 능력치, 100)
초과분 = Σ 선택 능력치별 4 × clamp((능력치 - 100) / 10, 0, 1) × 중요도
최종값 = 반올림(min(기본값 + 초과분, 100 + 4 × 선택 개수, 120))
```

기존 가중치가 큰 순서의 핵심 5개를 중요도 1로 잡아 **16개 포지션 × 기존 전술 스타일 10개 = 160가지**를 별도 계산했다. 실제 게임에 이 산식을 적용한 것은 아니다.

| 통제 조건 | 예시 산식 결과, 160가지 표시 OVR |
|---|---|
| 핵심 5개 110, 나머지 100 | 모두 120 |
| 핵심 5개 110, 나머지 95 | 117~118 |
| 핵심 5개 110, 나머지 90 | 115~117 |
| 현재 코드에서 모든 능력치 110 | 모두 100 |

따라서 **산식의 이론상 120은 성립하지만 정상 훈련으로의 도달은 미해결**이다. 나머지 스탯을 자동으로 100으로 만드는 방식은 미선택 성장 금지와 충돌한다. 현재의 연간 3개 훈련·재능·성장 둔화 나이를 유지한 상태에서, 기본 숙련과 100 초과 숙련을 어떻게 성장시킬지 먼저 정해야 한다.

권장 방향은 잠재력·기본 성장·스킬 초과 숙련의 한도를 구분하고, 선택은 상한만 열도록 만드는 것이다. 필요하면 문서가 예시로 제시한 기본값/초과분 환산을 조정하되, 모든 능력치의 기존 포지션 가중치를 보존하고 정상 진행으로 도달하는 사례를 먼저 검증해야 한다. 특정 최종 산식이나 재능별 새 수치는 이번에 확정하지 않았다.

새 수준표는 24개 행으로 0~120 정수를 모두 정확히 한 번 포함한다. 구간 누락·중복은 없으며 예시 수 불일치는 95~99 행 하나다. 실제 선수 이름은 주관적 비교 예시로 표시해야 한다.

추가 영향 범위:

- 경기 판정의 개별 상한을 110에 맞추되 성공률 한도는 별도로 유지한다. 표시 OVR 120을 세부 능력치 120으로 취급하면 안 된다.
- 현재 팀 전력에 사용자 OVR이 들어간다. 새 표시용 초과 환산 20점을 팀 전력과 개별 행동에 반복 가산하지 않도록 공통 경기 능력 척도를 정해야 한다. 선발·국대·주장 평가도 NPC와 같은 척도로 비교한다.
- NPC 전체에 새 세부 능력치 배열을 배분할 필요는 없다. 기존 단일 능력 표현·팀 기반 전력 보존을 유지하면서 사용자와의 비교 척도를 통일할 수 있다.
- 기존 몸값 능력항은 `(OVR-25)^3.35`, 주급의 능력항은 `(OVR-30)^3`이다. 100→120을 그대로 넣으면 해당 항만 약 **2.21배·2.13배**가 된다. 실제 최종 금액의 예측은 아니며, 구단 재정·이적 수요와 함께 상단 보정 검토가 필요하다는 뜻이다.

첨부된 France Football·UEFA·FIFPRO·FIFA 공식 링크 4개는 이번 환경에서 모두 네트워크 터널 **403**으로 접근하지 못했다. 연도별 원문 규정을 확인 완료했다고 보고할 수 없다. 현재 코드에도 `AWARD_VERIFICATION_NOTE`가 이 한계를 명시한다. 게임의 미래 시즌을 실제 공식 규정이 검증된 해처럼 표시해서도 안 된다.

50/30/20은 공식 배점이 아닌 게임 내부 권장안이다. 현 성과 점수는 50점 척도가 아니므로 기존 숫자에 능력 점수만 더하면 문서의 비중이 성립하지 않는다. 먼저 각 항을 정규화하고 출전 자격을 통과한 선수끼리 비교해야 한다. 리그·컵·세계 평가 기간을 분리하고, 국대 출전 기회가 없었다는 사유만으로 별도 0점 벌점을 추가하지 않는 방향이 적절하다.

시즌 평균이 아닌 평가 기간 중 능력을 반영하려면 사용자와 NPC의 능력 스냅샷도 같은 기준이어야 한다. 현재 세계 NPC 기록은 시즌 누계이고 월별 상세 누계는 사용자 소속 리그에 한정되어 있다(`extra-honours.ts:10–16`, `world.ts:230–241`). 공식상별 날짜 창을 정확히 적용하려면 필요한 기간별 요약을 추가해야 하며, 현재 시즌 누계를 그대로 여러 공식 평가 기간으로 간주하면 안 된다.

득점왕·도움왕·골든슈 같은 객관적 순위는 능력·낭만 점수를 받지 않는다. 주관적 상은 각 선정 주체에 맞는 평가 차이를 둔다. 후보·월드 11 전체 명단을 새 화면으로 추가하지 않고 본인 자격·순위·수상 결과와 사유만 UI·시즌 기록·TXT에 일관되게 연결할 수 있다.

현재 클럽 발전 이력은 최근 **5시즌**으로 제한된다(`world.ts:489`). 본인 시즌 상세에는 일부 발전 결과가 계속 남지만, 이것만으로 모든 클럽의 10~20년 무관·모든 NPC의 역사적 기록을 증명할 수는 없다.

최소 추가 데이터는 구단별 최근 주요 우승 연도·관측 시작 연도, 실제 기록 최고치와 근거, 대회 전 전력 요약, 선수별 필요한 부상·소속 요약 정도다. 모든 과거 경기 로그를 복제할 필요는 없다. 가점에는 사유·증거 ID·모형 버전만 저장하고 기존 경기 원장을 참조하면 된다.

총 +10 제한과 중복 감경만으로는 '큰 실적 격차를 뒤집지 않음'이 자동 보장되지 않는다. 기본 실적 자격과 근접 경쟁 범위를 함께 정해야 한다. 같은 우승의 언더독·승격·무관 종결 가점은 동일 사건으로 묶어 감경하고, 본인과 NPC에 같은 규칙을 적용해야 한다.

## 기능·성능을 보존하는 구현 순서

1. **공통 규칙부터**: 스킬 정의·개별 상한·새 척도 버전·잠금/수동 노화 예외·저장 호환 규칙. 기존 전술 스타일 보존.
2. **성장과 OVR**: 기본 잠재력과 초과 숙련 분리, 훈련 3개 유지, 새 수준표와 재능 성장 분포 보정. 각 포지션의 정상 육성 경로를 먼저 입증.
3. **경기·팀·선발 연동**: 110 실능력을 행동에 반영하고 팀 기반 전력 보존. 단순 OVR 중복 가산 없이 국대·주장·경제 산식을 함께 점검.
4. **수상과 근거**: 공식 규칙의 확인 범위 명시, 상별 독립 평가·기간, 객관적 순위 보호, 낭만 증거 요약·중복 제한. 과거 수상 결과 보존.
5. **UI·기록·회귀**: 훈련 하단 접이식 20/10 목록, 가독성·최대 5개·오류 안내, 본인 수상만 기록, TXT 연동, 장기 성능 검증 후 별도 배포 판단.

현재 클릭 지연을 줄인 저장 방식은 유지할 수 있다. 새 스킬 선택은 기존 경량 명령·작은 변경 저널 경로에 연결해야 한다(`client.ts:20`, `command-patches.ts:4`, `storage.ts:997`). 선택 클릭마다 전체 커리어 검증·복사·수상 재계산을 실행하는 구현은 피해야 한다.

수상·낭만 평가는 시즌/대회 종료 시 한 번 산출하고 저장한 결과를 표시한다. 경기 중에는 이미 수행하는 기록 집계 시 작은 증거 요약만 갱신하면 된다. 매 렌더에서 과거 모든 시즌·모든 대회·모든 선수를 재탐색할 필요가 없다. 기존 실제 경기 계산이나 세부 기록을 생략하는 방안은 필요하지 않다.

## 이번에 확인한 범위와 아직 확인하지 않은 범위

**이번에 실행한 확인:** 실제 키/함수 대조, 현재 성장 중단 사례, 현재 저장 110 거부, 160개 포지션·전술 조합의 예시 산식 계산, 320쌍의 현재 엔진 100/110 비교, 수준표 24행의 정수 구간 검사, 경제식 상단 항 비율 계산, 공식 링크 접근 확인.

**구현 후에 필요한 확인:** T01~T23 전체. 특히 치트 없이 모든 포지션·GK의 실제 120 육성, 85/90/95/100/110/120 여러 시드 성과 분포, 120도 우승이 보장되지 않는지, 상별 실제 자격·기간·객관적 득점 순위, 옛 저장·확정 수상·은퇴 TXT 보존, 10~20시즌 이후 클릭·저장·메모리 측정이다. 이번 산술 계산으로 실제 육성 테스트를 통과했다고 대신 보고하지 않는다.

신규 기능은 구현하지 않았으므로 신규 UI 실브라우저 검증이나 새 장기 시뮬레이션은 수행하지 않았다. 이전 개선본에서 통과한 회귀 검사는 이번 수정본 구현의 검증 결과로 전용할 수 없다. 실제 Windows Edge의 로컬 파일 실행 성능도 이번 검토에서 측정하지 않았다.

미해결 핵심은 최종 성장/OVR 산식·재능별 분포, 상별 연도 규정·평가 기간 검증, 부족한 낭만 근거의 저장 설계다. 이들은 구현 단계에서 검증 가능한 규칙으로 구체화해야 한다. 게임 실행 코드와 배포본은 이번 검토로 변경하지 않았다.
