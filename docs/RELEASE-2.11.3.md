# K볼 2.11.3 · 수비수 수상·장기 구단 성장 균형

## 조사 범위와 결론

사용자는 92 수비수로 여러 구단에서 리그 우승 14회와 여러 챔스 우승을 기록했으나 발롱도르 30인에 들지 못했다고 제보했다. 확인한 성향은 **유관력 10·리더십 6**이다. 실제 사용자 저장·총 커리어 시즌 수·이적 구단·세부 포지션·능력 배분은 확인하지 못했으므로 14회 자체가 과도하다고 단정하거나 해당 저장을 재현했다고 주장하지 않는다.

코드와 독립 대조에서 두 문제를 확인했다. 수비수의 수상 평가에는 실제 입력 누락과 포지션 간 비교 편향이 있었고, 장기 구단 성장에는 전력 우위가 중첩되는 구간이 있었다. 수상과 팀 승리를 별도로 조정한다. 우승 횟수·후보 인원에 주인공 전용 보장이나 상한을 두지 않는다.

## 수비수 평가

- 기존 `roleContribution`과 대회 평가식은 수비수의 무실점을 읽었지만, 경기 엔진은 골키퍼에게만 무실점을 생성했다. 수비수는 항상 0을 넣고 평가받았다. 이제 수비수가 실제 60분 이상 뛰고 자신의 출전 구간에 실점하지 않았을 때 기존 `cleanSheets`에 기록한다. 교체 뒤 실점과 출전 중 실점을 실제 골 시각으로 구분한다. GK 처리는 유지하며 슈팅·득점·승패를 바꾸지 않는다.
- 세계 투표는 기존에도 리그 내 포지션별 기여를 평가했으나, 마지막 개인 점수를 공격수와 같은 전역 척도로 나눴다. 골·MOM의 높은 분포가 불리함을 남겼다. 역할별 기준을 추가해도 원래 80점 하한을 그대로 쓰면 실제 대조의 GK·DF·MF·FW 척도가 모두 80으로 같아져 보정이 사라졌다. 최종 모형은 최소 5명의 실제 900분 이상 표본에서 포지션군별 95백분위×1.15, 하한 65를 사용한다. 표본이 작으면 기존 전역 기준을 사용한다.
- 리그 수준 가중은 그 전에 적용하고 개인 점수 상한·실제 출전 자격·팀 업적·능력·징계·스타성·근거 있는 성취 평가는 유지한다. 객관적 득점왕/골든슈는 바꾸지 않는다. 같은 평가를 NPC와 주인공에게 적용한다.

새 지속 필드나 저장 스키마는 추가하지 않는다. 과거 경기의 무실점 0이나 확정한 수상을 소급 생성하지 않는다. 이후 경기에서 올바른 무실점이 쌓이고, 아직 확정되지 않은 이후 시즌 심사에 새 모형을 적용한다. 평점·OVR·성장·플레이스킬 산식은 유지한다.

## 팀 영향력

볼 소유 우위는 모든 선수의 볼 유지 능력을 상대 팀 전력과 비교해 더했다. 팀 전력·기술 대결에서도 이미 반영한 평범한 선수단 우위가 다시 10명 단위로 쌓일 수 있었다. 이제 상대와 자기 팀의 기준 전력 중 높은 값을 넘어서는 개인의 특별한 볼 유지 기여를 계산한다. 자기 팀보다 강한 상대를 만나는 뛰어난 선수의 비교 기준은 유지한다. 수비·빌드업·슈팅·실제 캐리와 지휘 효과를 삭제하지 않는다.

장기 성장에서는 명성 상승과 투자 전력을 합한 값을 선수단 전체의 경기 전력으로 거의 그대로 바꾸고 있었다. 한 구단이 다른 강팀보다 크게 높은 평균 기량을 계속 유지할 수 있었다. 기본 전력에 성장분을 합한 값이 86을 넘는 구간부터 추가 성장의 효율이 점차 완만해지는 곡선을 적용한다. 일반 명단의 조건에서는 연간 폼·주인공의 실제 기여를 더하기 전의 성장 전력이 90.5 부근에 점차 접근한다. 최종 팀 전력의 일률적인 90.5 상한은 아니다. 원래 기본 전력·명성·지급한 투자·예산·과거 성장 이력은 그대로 남는다.

약팀이 상위권으로 성장하는 낮은 구간은 유지하고, 유관력 10·리더십 6의 효과도 유지한다. 이미 부풀어 있던 팀은 다음 실제 전력 계산부터 새 변환을 적용하지만 과거 결과는 바꾸지 않는다. 모든 구단의 우승 확률을 균등하게 만드는 조정은 아니다.

## 실제 시즌과 같은 기록 재평가

모든 필드 능력치를 92로 고정한 26세 선수, 동일 시드로 세계 리그·국내 컵·대륙 대회·국대까지 한 시즌씩 실제 진행했다. 고성향 조건은 유관력 10·리더십 6, 나머지는 5다. 중립 대조는 모두 5다. 실제 기용·부상을 적용했으며 사용자 세이브 재현과 구분한다.

| 조건 | 2.11.2 발롱 전체 순위 | 최종 2.11.3 |
|---|---:|---:|
| CB·인테르·중립·리그 우승 | 51위 | 27위 |
| CB·레스터·중립·중위권 | 129위 | 30인 밖 |
| RWB·인테르·유관력 10/리더십 6·리그 우승 | 44위 | 15위 |
| RW·인테르·중립·리그 우승 | 3위 | 5위 |
| CB·레알·유관력 10/리더십 6·리그와 UCL 우승 | 19위 | 3위 |
| RWB·레알·유관력 10/리더십 6·리그와 UCL 우승 | 12위 | 3위 |

개선 전에도 UCL 우승 수비수가 후보가 된 사례가 있다. 수비수를 코드로 무조건 배제하는 문제로 표현하지 않는다. 처음 인테르 CB 대조에서 구버전 30인은 수비수가 0명이었고, 새 대조에서는 수비수가 들어왔다. 92라는 숫자나 팀 우승만으로 항상 후보가 되지는 않는다.

위 전후 표는 경기 계산도 달라져 새 득점·다른 컵 결과까지 일부 달라진다. 수상 모형만의 효과를 분리하기 위해 **기존 레알 CB/RWB의 동일 경기·NPC 성적을 고정한 분석용 재심사**도 수행했다. CB **19→4위**, RWB **12→3위**였다. 실제 기존 저장을 열어 그대로 평가했을 때는 원래 수상과 순위를 유지하는 것도 따로 검증했다. 분석용 재심사 결과를 사용자 이력에 쓰지 않는다.

## 독립 리그 대조

실제 EPL 선수단·38경기 전체 일정과 조건별 동일한 16개 시드로 비교했다. 개인 출전은 90분으로 고정한 상한 노출 대조다. 대응하는 주인공 외 경기의 실제 계산 결과를 공유하며, 출전 없음 대조는 선수단과 팀 전력에서 모두 주인공을 제외한다. 아래 성장 조건은 **명성 95·재투자 전력 7을 명시한 독립 통제 시나리오**이며, 16년의 실제 성장 커리어가 아니다.

| 성장 구단·92 CB | 이전 우승/16 | 이후 우승/16 | 이전→이후 평균 승점 |
|---|---:|---:|---:|
| 첼시·중립 | 16 | 11 | 107.19→94.44 |
| 첼시·유관력 10/리더십 6 | 16 | 14 | 109.00→99.50 |
| 리버풀·중립 | 16 | 16 | 112.06→103.31 |
| 리버풀·유관력 10/리더십 6 | 16 | 16 | 113.19→106.19 |
| 레스터·중립 | 13 | 11 | 103.25→94.50 |
| 레스터·유관력 10/리더십 6 | 14 | 14 | 105.50→100.81 |

가장 강하게 성장한 리버풀은 이 표본에서 여전히 16회 우승했다. 개선으로 모든 강팀의 독주 가능성이 사라졌다고 주장하지 않는다. 유관력 최대치와 매우 좋은 선수단에서는 여전히 우승이 잦다.

초기 레스터의 중립 92 CB는 새 대조에서 평균 50.56점·10.13위, 같은 팀의 75 CB는 37.94점·15.50위였다. 유관력 10이면 92 CB는 56.38점·8위였다. 초기 첼시의 고성향 92 CB는 68.06점·4.88위였고, 성장한 첼시에서는 우승 경쟁을 했다. 개인의 긍정적인 기여와 실제 구단 성장에 따른 차이를 유지한다.

## 최종 검수

코어 검사 **367개 중 366개 통과·실패 0·30시즌 전체 재시뮬레이션 1개 제외**. 실제 출전 구간의 무실점·교체·60분 자격, 역할별 투표 척도, 충분한 기여 없는 능력/팀 우승의 한계, 투자 기록 보존과 성장 효율을 새 회귀 검사로 확인했다. 이전 Worker 진도 검사에서 수명 제어에 필요한 `history`가 없던 테스트용 가짜 Career도 보완했다. 실제 게임 명령을 우회하거나 안전 검사를 줄이지 않았다.

새 92 CB 실제 커리어는 JSON 전체 검증·체크섬·전 필드 왕복과 한국어 TXT를 통과했다. 최종 독립 HTML에서 기존 **272,717,105바이트·14시즌** 저장을 가져와 저장·재실행·JSON 내보내기를 통과했고, 새 슬롯 ID만 제외한 모든 필드가 원본과 같았다. 확정 수상과 과거 기록도 보존했다. PC/모바일 실제 플레이 흐름 **11항목**도 통과했다.

검수 브라우저는 Linux Chromium이다. 관리형 브라우저의 file:// 차단으로 같은 독립 HTML을 localhost로 전달했으며 Windows Edge 직접 검수와 구분한다. 대용량 검수는 다른 코어/실제 시즌 검사와 동시에 수행했으므로 시간을 2.11.2 성능 대조와 비교하지 않는다. 2.11.2의 저장 인코딩·Worker 수명·경량 변경 경로는 그대로다. 새 보조 자료는 판정 호출/경기 안에서만 유지하며 과거 기록을 복제해 쌓지 않는다.
