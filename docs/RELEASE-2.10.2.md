# K볼 2.10.2 · 하부리그 득점 균형

## 재현한 문제

2.10.1에서 실제 페스카라 선수단과 세리에 C B조의 38경기 일정을 사용했다. 필드 능력치를 모두 65 또는 70으로 고정하고, 포처·기본 성향·건강한 상태·매 경기 90분 출전으로 같은 20개 시드를 비교했다. 이는 선발·부상·피로가 누적되는 실제 커리어와 구별하는 통제 실험이다. 사용자의 특정 저장을 재현한 것은 아니다.

- 65: 평균 24.6골, 30골 이상 3/20시즌.
- 70: 평균 32.15골, 30골 이상 13/20시즌, 40골 이상 2/20시즌.
- 주인공 없는 세리에 C B조 3개 시즌은 경기당 평균 약 3.39골이었다.

확인한 원인은 하위 능력 GK의 **낮은 기본 선방률**과 **절대 수치만으로 계산한 수비 조율**이 겹치는 구조다. 비슷한 수준끼리 뛰는 하부리그도 GK가 낮은 수치라는 이유만으로 찬스가 더 많이 생기고 쉽게 득점했다. 뛰어난 선수의 우위와 별개로 득점 환경 자체가 높았다. 두 산식은 직전 패치에서도 충분히 교정되지 않았다.

## 최소 수정

1. 일반 슈팅의 기본 선방 곡선을 수정했다. 65 대 65의 유효 슈팅 선방 확률은 79.9%→85.86%, 80 대 80은 86.8%다. 낮은 절대 능력에서도 기본적인 슈팅 방어가 유지되고, 실제 마무리/골키퍼 기량 차이는 하나의 유한한 대결 항으로 반영한다. 1~110 전 구간에서 골키퍼를 높이면 선방 확률이 오르고 마무리를 높이면 내려간다.
2. GK 수비 조율을 출전한 동료 필드 선수 기량의 중앙값과 비교한다. 65 GK·65 수비진과 80 GK·80 수비진의 중립 기회 억제는 같고, 같은 수비진에서 조율을 높이면 상대 슈팅이 줄어든다. 낮은 GK 수치 자체가 하부리그 전체의 슈팅을 늘리는 현상을 제거했다.

양 팀·NPC·주인공에게 같은 판정을 쓴다. 직접 찬스 창출·팀 기여·포지션·스타일·골키퍼 개별 능력·후반 체력·출전 시간은 유지한다. 골 수 상한이나 시즌 목표 수치, 경기 후 감산, 과거 기록 재계산은 없다. 일대일·페널티의 기존 별도 판정과 슈팅→득점/선방→도움의 원장도 유지한다. OVR·플레이스킬·성장·수상·저장 형식·UI는 수정하지 않았다.

## 같은 20개 일정의 수정 전후

다음은 **매 경기 90분을 강제한 일정 대조 평균**이다. 실제 플레이에서 보장되는 득점 수가 아니다. 포처/인사이드 포워드의 전 능력치가 동일하며 특정 실존 선수를 그대로 모델링한 프로필도 아니다.

| 소속/포지션 | 능력치 | 경기 수 | 평균 득점 이전→수정 | 수정 후 30골 이상 시즌 |
|---|---:|---:|---:|---:|
| 페스카라 ST · 세리에 C | 65 | 38 | 24.60 → 18.90 | 0/20 |
| 페스카라 ST · 세리에 C | 70 | 38 | 32.15 → 25.40 | 4/20 |
| 케임브리지 ST · 잉글랜드 3부 | 65 | 46 | 20.95 → 15.60 | 0/20 |
| 케임브리지 ST · 잉글랜드 3부 | 70 | 46 | 29.10 → 22.75 | 1/20 |
| 아우에 ST · 독일 3부 | 65 | 38 | 20.55 → 15.45 | 0/20 |
| 아우에 ST · 독일 3부 | 70 | 38 | 26.60 → 21.10 | 0/20 |
| 토트넘 LW · EPL | 90 | 38 | 26.85 → 25.45 | 5/20 |
| 토트넘 LW · EPL | 95 | 38 | 34.95 → 32.55 | 15/20 |
| 토트넘 LW · EPL | 100 | 38 | 45.65 → 42.00 | 19/20 |

| 리버풀 ST · EPL | 100 | 38 | 59.55 → 54.45 | 20/20 |

65와 70의 모든 3부 대조에서 수정 후 40골 이상은 없었다. 페스카라 70의 최대치는 39골로, 예외적으로 높은 한 시즌을 금지하는 방식은 아니다. 세부 슈팅·유효 슈팅·도움·일대일·페널티·팀 득실점 및 각 시드의 전체 결과는 검수 자료에 남긴다.

높은 선수의 상대 우위도 유지한다. 같은 페스카라의 90은 평균 65골, 98은 87.95골이었다. 특히 후자는 **20개 능력이 모두 98인 극단적 프로필**로, 3부 전 경기 풀타임이라는 실험 조건에서 여전히 과도할 수 있는 상단 사례다. 이 패치는 모든 OVR·모든 리그의 현실성을 완성했다는 주장을 하지 않는다. 사용자가 지적한 65~70 구간과 하부리그의 기본 득점 환경을 우선 바로잡는다.

## 주인공 없는 리그

각 리그 실제 전체 일정 3개를 계산한 경기당 평균 골이다. 주인공을 출전시키지 않으며 일부 경기만 추출하지 않았다.

| 리그 | 이전→수정 |
|---|---:|
| 세리에 C B조 | 3.390 → 2.423 |
| 잉글랜드 3부 | 3.435 → 2.686 |
| 독일 3부 | 3.407 → 2.640 |
| EPL | 2.768 → 2.692 |

## 검수 자료

필드 20개·GK 10개 맥락에서 하나씩 90→100으로 바꾼 동일 시드 300경기 대조 **30개 모두 기존의 의도한 효과를 유지**했다. [능력치 대조](validation/release-2.10.2/ability-links.json)

실제 세계 전체 커리어도 별도 시드로 2개 진행했다. 페스카라의 65 ST는 38경기·3,091분·21골·6도움·팀 16위, 70 ST는 38경기·3,247분·20골·5도움·팀 5위였다. 두 커리어는 시드가 다르므로 이 두 득점만으로 기량 효과를 비교하지 않는다. 기량 대조는 위의 동일 20개 시드 결과를 사용한다. 두 커리어 모두 훈련 0개·능력치 잠금·기본 성향이며 능력치는 실제로 그대로 유지됐다. 경기 원본의 네 신규 지표와 누적 수치, JSON 내보내기/불러오기, 한국어 TXT를 검증했다. [실제 시즌 결과](validation/release-2.10.2/actual-careers.json)

OVR·성장·스킬·수상·저장·TXT·구단 기반·UI 등 기존 18개 소스 파일이 2.10.1과 바이트 단위로 같다. [보존 검증](validation/release-2.10.2/preserved-systems.json) · [수정 전 전체 일정](validation/release-2.10.2/scoring-before.json) · [수정 후 전체 일정](validation/release-2.10.2/scoring-after.json)

전체 코어 **330개 중 329개 통과·실패 0개·기존 30시즌 검사 1개 제외**다. 별도 신규 검사 4개는 선방 확률의 방향성과 실제 세 리그의 20시드 분포를 확인한다. 기존 고능력 100→110·필드/GK 전 항목·순위·도움·원장·성장/잠금·FA·부상·수상·기록 검사를 유지했다. [코어 집계](validation/release-2.10.2/core-summary.json) · [원본 TAP](validation/release-2.10.2/core-suite.tap)

최종 단일 HTML의 플레이 흐름 11항목을 통과했다. 새 경기·훈련·반 시즌/다음 시즌·이적·백업·은퇴·치트·모바일 GK를 확인했다. 구버전 2.9.5/2.10.0·혼합 집계·은퇴·12시즌·새 70 선수 저장 총 7개를 불러와 원본 경기·클럽/국대/대회/통산 수치·한국어 TXT·재내보내기·재실행을 대조했다. 페이지 오류와 외부 자산 요청은 없었다. 브라우저 검수는 Linux Chromium에 다운로드용 HTML을 HTTP로 전달했으며 Windows Edge 파일 실행을 직접 측정한 것은 아니다. 단일 HTML에서는 별도 PWA 오프라인 캐시 검사가 적용되지 않아 해당 항목만 제외한다. ## 성능 비교

다른 검사가 종료된 동일 기계에서 2.10.1과 최종 소스를 번갈아 측정했다. Linux Node 측정이며 Edge의 직접 실행 지연을 뜻하지 않는다.

- 원본 보존 경기 1,000회·5회 중앙값: 873.94→908.30ms, +3.93%.
- 집계 후 버리는 NPC 경기 1,000회·5회 중앙값: 794.07→807.76ms, +1.72%.
- 세계 전체/커리어 2라운드·3회 중앙값: 941.98→996.17ms, +5.75%·약 54ms. 양쪽 모두 리그 726경기를 계산했다.

작은 추가 비용은 있으며 기존 Worker·작은 변경 저장·실제 경기 원본 보존을 유지한다. 기능이나 경기 계산을 생략하지 않았다. [순수 엔진](validation/release-2.10.2/engine-performance.json) · [세계 진행](validation/release-2.10.2/world-performance.json)
