# 배포 대기 · 장기 저장과 클릭 지연 개선

> 후속 배포 요청에 따라 2.7.3으로 통합했습니다. 현재 최종 검수·배포 상태는 [2.7.3 릴리스 기록](RELEASE-2.7.3.md)을 확인하세요. 아래는 당시 개발 검증 기록입니다.

2026-10-25 · 로컬 개발 버전 **2.7.3-dev.2**. 기존 부상·주장·팀 기여·은퇴 기록 패치를 포함합니다. 사용자 요청에 따라 푸시·배포·새 플레이용 HTML/ZIP 생성과 업로드를 보류했습니다. 기존 공개 ZIP은 2.7.2 그대로입니다.

## 확인한 병목과 수정

첨부된 아스트라 v6의 실제 실행 코드를 분석한 뒤 적용했습니다. 아스트라는 가벼운 설정 조작에서 전체 저장을 호출하지 않고 필요한 상태만 복사합니다. K볼도 작은 엔진 명령 자체는 빨랐지만, 매 명령 뒤 전체 과거 기록을 검증·직렬화·복사하고 IndexedDB에 중첩 객체를 넣는 동안 입력을 잠갔습니다. 로컬 HTML이라는 이유만으로 지연이 생긴다고 결론 내리지 않았습니다.

- **작은 명령도 즉시 디스크에 저장**: 잠금·전체 잠금·수동 노화·훈련 확정·치트 설정·치트 증가는 내부 엔진이 만든 변경만 SHA-256으로 연결한 변경 기록에 저장합니다. 슬롯·직전 정상 백업·메타데이터가 한 IndexedDB 트랜잭션으로 반영된 뒤 조작을 받습니다. 저장을 생략하거나 저장 전에 ‘자동 저장됨’을 표시하지 않습니다. 엔진 경로·리비전·공유된 과거 기록·변경 내용·이전 상태가 맞지 않으면 기존 전체 검증 경로로 처리합니다.
- **전체 스냅샷은 배경에서 합치기**: 마지막 조작 1.5초 뒤 저장 Worker가 전체 검증·기존 형식의 체크섬·스냅샷 생성을 합니다. 새 명령은 그동안에도 별도 변경 기록으로 저장합니다. 완료 시 검증한 지점까지만 합치고 그 이후 변경과 직전 정상 백업을 보존합니다. 창을 닫아 중단돼도 다음 불러오기에서 검증·복원한 후 배경 합치기를 이어갑니다.
- **IndexedDB에는 Blob 저장**: 전체 기록을 UTF-8 JSON Blob으로 보관해 메인 스레드의 중첩 객체 복사 비용을 줄였습니다. 저장 Worker는 일반 저장 때 전체 Career 객체를 화면에 다시 보내지 않습니다. 기존 객체 슬롯은 전체 검증 후 원자적으로 변환하며, JSON 내보내기 형식·스키마·기존 체크섬 바이트는 유지합니다.
- **큰 문자열·중복 순회 줄이기**: 체크섬은 기존 정렬·Unicode 처리와 정확히 같은 바이트를 작은 버퍼로 만듭니다. 은퇴 기록은 공통 경기 원장을 재사용하고 펼친 화면만 세부 행을 생성합니다. 경기의 0 스탯 객체와 동일 구단·시즌의 결정론적 폼 값은 재사용 가능한 생성 구조로 바꿨습니다. 현재 전력·선수·성장·부상·재정은 계속 실제 값으로 계산합니다. 캐시는 WeakMap으로 과거 커리어의 수명을 늘리지 않습니다.

NPC 선수단, 모든 실제 계산 대상 경기·리그·컵·국대, 개인 성장, 수상, 과거 기록의 보관 범위를 줄이지 않았습니다. 전체 진행 명령·가져오기·불러오기·전체 저장에는 완전한 검증을 유지합니다. 가벼운 명령만 인증된 변경을 먼저 저장하며 전체 검증을 배경에서 다시 수행합니다.

## 실측과 보존 검증

같은 실제 20시즌 JSON(119,924,636바이트)과 Linux Chromium 154, localhost HTTP 환경입니다. 이전 2.7.2는 포장 방식별 한 번의 잠금 조작, 이번 개발본은 연속 20회 조작을 측정했습니다. 사용자 Windows Edge의 보장 시간이나 반복 통계상 속도 배수로 해석하지 않습니다.

| 항목 | 기존 2.7.2 웹 | 이번 개발본 웹 |
| --- | ---: | ---: |
| 잠금 클릭 → 저장 완료·입력 해제 | 20,756.9ms (1회) | 중앙값 45.8ms, 범위 39.0~57.6ms (20회) |
| 해당 조작의 IndexedDB put 호출 합계 | 약 3,850ms | 0.1~1.1ms |
| 조작마다 전체 Career를 저장 Worker로 전송 | 예 | 아니오 |

기존 단일 HTML을 HTTP로 연 경우 저장 완료는 30,247.9ms였습니다. 이번 단일 HTML 전체 화면의 시간과 직접 비교한 숫자는 아닙니다. 단일 HTML용 어댑터는 파일 생성 없이 번들 구문을 검사하고, Blob Worker를 실제 실행해 구버전 전체 파일의 검증·저장 준비·복원을 대조했습니다.

- 20시즌: 배경 합치기 중에도 조작 10회가 추가 저장됐고, 수동 노화 후 재실행 시 잠금·능력치·현재 시즌 스탯·모든 과거 시즌 스탯과 경기 ID가 같았습니다. 재실행 후 배경 합치기가 리비전 519까지 완료되고 변경 기록은 0개가 됐습니다. 다시 재실행해도 결과가 같았습니다.
- 경기 결과: 수정 직전 개발본과 같은 시드로 ST·LWB·GK를 각각 2라운드 진행했습니다. 세계 선수·국대·컵·순위표를 포함한 **전체 Career JSON의 SHA-256이 세 경우 모두 일치**했고 입력 원본도 보존됐습니다. 계산을 없애서 만든 속도 개선이 아닙니다.
- 저장 회귀 47개: 구버전 체크섬, Unicode·긴 문자열의 바이트 일치, 작은 변경의 모든 필드 복원, 백업·복구, 중복 전체 저장, 손상된 변경 기록, 조작된 엔진 결과, 다른 탭 충돌, 합치기 중 새 명령, 삭제된 슬롯 재생성 방지, Worker 취소·시간 제한·타이머 정리를 확인했습니다.
- 30시즌 은퇴 파일: 81,104,879바이트 저장을 가져와 자동 저장·재실행 후 TXT를 내보냈습니다. 클럽 1,020경기·국대 108경기의 연도별·통산 스탯을 대조했고, **86,443바이트 TXT가 수정 전 파일과 SHA-256까지 일치**했습니다. 다운로드는 1회이며 슬롯 ID·리비전·검사값은 바뀌지 않았습니다. PC·모바일 화면도 확인했습니다.
- 타입 검사·웹 빌드·단일 HTML 어댑터의 무출력 검사 통과. 기존 훈련·잠금·수동 노화·모바일 UI 검사도 통과했습니다.

## 남은 한계

이 환경은 직접 `file://` 이동을 관리 정책으로 막습니다. 실제 Windows Edge 로컬 파일 검증과 새 단일 HTML 전체 UI 검증을 완료했다고 표시하지 않습니다. 배포 요청 시 해당 포장에 대한 검증이 별도로 필요합니다.

세밀한 경기·선수 기록 자체는 계속 누적됩니다. 이번 검사에서 20시즌 불러오기 후 메인 JS 힙은 GC 뒤 약 110.6MB로, 메모리 사용량 자체가 크게 줄었다고 주장하지 않습니다. 전체 시즌 계산·최초 가져오기·큰 JSON 내보내기는 여전히 전체 데이터 크기의 영향을 받습니다. 5.44초는 재접속 후 이미 진행 중인 배경 합치기를 기다린 시간이며, 모든 전체 저장이 그 시간 안에 끝난다는 뜻이 아닙니다.

재검증: `npx tsx --test src/game/{canonical-bytes,save-performance,save-preparation,client-progress,storage,career-text}.test.ts`, `node tests/kball-save-performance.test.mjs`, `node tests/kball-blob-worker.test.mjs`, `npm run build`, `node scripts/build-playable.mjs --check-only`. 브라우저 검사는 실행 중인 4173번 웹 빌드와 이전에 실제 생성한 장기 저장 파일이 필요합니다. `--check-only`는 플레이용 HTML·ZIP을 쓰지 않습니다.
