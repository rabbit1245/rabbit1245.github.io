# K볼 2.10.0 · 선수 개성과 경기 행동 4종

## 변경 범위

헤더 득점·압박 성공·전진 패스 성공·GK 펀칭 성공을 실제 행동 판정에 연결했다. 이 업데이트는 플레이스킬 선택·상한·OVR·성장·개인상 판정·기존 선수 유형의 산식을 수정하지 않는다. 같은 기존 플레이스타일과 OVR에서도 세부 능력치 조합에 따라 다른 행동을 한다. 바뀐 경기 결과와 기존 기록이 이후 기존 평점·수상 평가에 반영될 수는 있지만 신규 지표에 별도 수상·평점 가점을 추가하지 않았다.

### 헤더 득점

기존 슈팅 기회에서 헤더를 선택할 가능성은 포지션·헤딩·점프력·위치 선정·몸싸움·다른 마무리 능력과 동료 크로스 공급에 따른다. 실제 공급자와 수비수를 선택하고 공중볼 경합에 이긴 뒤 슈팅한다. 센터백의 헤더는 실제 코너킥/프리킥 공급 이벤트를 거친다. 헤더의 유효 슈팅과 골키퍼 판정에도 관련 능력치를 사용한다.

득점 이벤트는 헤더 슈팅 → 공중볼 경합 → 크로스 → 필요한 경우 세트피스로 연결된다. 헤더 도움을 기록할 때도 이 실제 크로스 공급자에게 귀속한다. 헤더 득점은 기존 득점 1회의 하위 지표다. 팀 점수와 개인 득점을 추가로 올리지 않는다. 기존 공중볼 경합 기록도 유지하며 새 헤더 경합은 실제 시도·승리로 각각 한 번 반영한다.

### 압박 성공

포지션·출전 시간·활동량·스피드·기존 압박 역할은 압박 기회를 바꾼다. 수비력·예측력·팀워크·판단력·속도·체력을 상대 볼 소유자의 볼 컨트롤·침착력·패스와 비교한다. 상대 처리를 방해하는 데 성공해도 별도의 회수 경합에서 실제 소유권을 얻어야 압박 성공이다. 동료가 회수해도 원인이 된 압박 선수에게 기여를 기록한다.

압박 이벤트에는 상대 볼 소유자와 소유권 ID, 회수 이벤트에는 원인 압박과 이전 소유 팀을 남긴다. 이 회수는 태클·인터셉트 성공으로 다시 세지 않는다. 기존 독립 태클·차단은 유지한다. 실제 성공한 압박은 팀의 상대 찬스 억제에 반영된다.

### 전진 패스 성공

현재 엔진에는 연속 공간 좌표가 없다. 수비 진영 → 중원 → 공격 진영 → 박스의 공격 단계 전환을 판정한다. 패스 전에 출발 구역·진행 의도·도착 구역·활성 동료 수신자를 정하고, 패스·시야·판단력·볼 컨트롤·전환 거리·상대 전력으로 실제 성공을 판정한다. 횡/후방 성공은 새 기록에 포함하지 않는다.

이 단계 전환은 기존 전체 패스 시도 안에 포함한다. 나머지 일반 패스의 기존 집계 방식을 유지하며, 전체 패스 성공과 별개로 패스 수를 늘리지 않는다. 성공한 전진 패스는 일반 성공 패스보다 높은 전개 가중치를 적용하되 동일 패스를 두 번 합산하지 않는다.

### 골키퍼 펀칭 성공

상대 공급자가 보낸 실제 크로스마다 압박과 핸들링·공중 장악·판단력·GK 위치 선정으로 포구/펀칭을 선택한다. 성공적으로 잡아 보유한 공은 포구, 펀칭해 위험 지역 밖으로 보낸 공은 펀칭 성공으로 기록한다. 실패해 위험 지역에 남은 공은 성공으로 세지 않는다. 동일 크로스에 두 행동을 중복 기록하지 않고 선방·스위핑도 별도로 집계한다.

### 역할·100 초과 능력치

포지션별 행동 기회·기존 패스/압박 역할·팀 전력 및 기존 전술 계산·상대 전력·실제 교체/퇴장 시각을 반영한다. 능력치가 있는 선수는 원래 수치 110까지 판정에 사용한다. 100 이상을 일괄 100으로 자르지 않는다. 개별 능력치가 없는 기존 NPC 자료만 기존 전력을 대체값으로 쓴다. 새 선수 유형이나 플레이스킬은 만들지 않는다.

## 표시·저장·기록

- 필드: 기존 포지션별 순서의 9칸을 보존하고 신규 3칸을 뒤에 붙인 **6칸 × 2줄**이다. 두 번째 줄 마지막 세 칸은 헤더 득점·압박 성공·전진 패스 성공이다. 기존 영역 안에서 여백을 조정하며 별도 탭·창·가로 스크롤을 추가하지 않는다.
- GK: 기존 9칸의 순서를 유지하고 마지막 오른쪽 아래에 펀칭 1칸을 추가한다.
- 경기 상세·라커룸 시즌 합계·시즌 이력·대회 필터·클럽/국대·통산·은퇴 화면/TXT·JSON에 같은 지표를 연결한다.
- 새로운 경기 원본은 `actionVersion: 1`과 구조화된 행동·인과 ID를 보존한다. 기존 `metricsVersion: 2`와 저장 형식은 그대로다. 새 집계 경기 수/분으로 실제 집계 범위를 보존한다.
- 기존 파일의 해시를 먼저 검증하고 과거 기록에 값을 주입하지 않는다. 과거 원본이 없으면 **미집계**, 신규 원본에서 발생하지 않았으면 **0**이다. 혼합 통산은 신규 집계 값에 `*`와 집계 경기 범위를 표시하고, 과거 미집계 시간은 90분당 계산에서 제외한다. 모호한 과거 텍스트를 새 지표로 추정하지 않는다.

## 중복·정확성 검사

저장 검증은 헤더 ≤ 전체 득점, 전진 패스 ≤ 패스 성공, 포구+펀칭 ≤ 상대 크로스와 집계 경기/시간 범위를 확인한다. 소유권 회복 없이 압박 성공을 기록하거나 같은 소유권을 두 번 회수할 수 없다. 같은 크로스의 포구/펀칭 중복, 같은 공급의 헤더 중복, 원인 압박·크로스와 태클/차단/선방/스위핑/공 처리의 중복을 거부한다. 실제 선수·팀·출전 시점과 원본 이벤트 합계를 대조한다.

경기별 수치는 이 원본과 검증하고, 시즌·대회·통산은 기존 경기 집계 경로로 합산한다. 세계 NPC 리그/컵에서 선수 집계 직후 버리는 임시 경기에는 동일 계산·난수·결과를 유지하면서 버릴 새 로그 객체의 생성만 생략한다. **주인공 경기와 국가대표 경기의 새 원본은 상세 연출 여부와 무관하게 보존한다.** 임시 계산의 로그 생략 옵션으로 이 원본을 끌 수 없다.

행동 조회는 경기당 이벤트 인덱스와 단일 순회, 활성 명단·구역·공급자·공중볼 능력의 경기 객체별 WeakMap 캐시를 사용한다. 커리어 전체를 클릭마다 재집계하거나 매 선수마다 전체 경기 이벤트를 반복 검색하지 않는다. 새 정수 카운터는 정확한 정수 덧셈을 사용해 불필요한 소수점 변환을 없애고, 기존 지표의 반올림 경로는 유지했다.

## 성능 측정과 한계

동일 기계에서 2.9.6 원본과 최종 코드를 번갈아 실행했다. 다른 코어/브라우저 검사가 종료된 뒤 측정했으며 Linux Node 20 결과다. 실제 Windows Edge의 클릭 지연 측정치를 뜻하지 않는다.

|---|---:|---:|---:|
| 전체 세계 + 커리어 2라운드, 726개 리그 경기, 3회 중앙값 | 793.75ms | 971.68ms | +22.4% · +177.93ms |
| 동일 경기 1,000회, 새 원본 보존, 5회 중앙값 | 591.23ms | 902.95ms | +52.7% · 경기당 +0.312ms |
| 집계 뒤 버릴 NPC 경기 1,000회, 동일 계산, 5회 중앙값 | 605.42ms | 843.41ms | +39.3% · 경기당 +0.238ms |

새 행동을 실제로 판정하고 원본을 보존하므로 **계산 비용이 이전과 같다고 주장하지 않는다**. 기존 Worker 실행·작은 변경 저장·지연 로딩은 유지하고, 새 UI는 저장된 합계를 읽는다. 캐시·단일 순회·정수 집계와 버릴 NPC 로그 객체 생략으로 불필요한 비용을 줄였다. 마지막 방식은 계산·능력치 효과·통계·점수·평점이 원본 보존 모드와 완전히 동일함을 별도 검사한다. 주인공·국대 경기 원본은 생략하지 않는다.

위 수치는 고정 검수 선수·명단·시드에서의 비교이며 모든 리그·기기·장기 저장의 속도를 보장하지 않는다. [순수 엔진](validation/release-2.10.0/engine-performance.json) · [세계 전체 진행](validation/release-2.10.0/world-performance.json) · [엔진 벤치마크](../scripts/benchmark-action-engine.ts) · [세계 벤치마크](../scripts/benchmark-action-world.ts)

## 실제 기록 화면 검수

최종 HTML에 신규 CB/GK 2시즌·이전 버전 1시즌·혼합 저장·은퇴 저장·12시즌 혼합 저장, 총 **6개 JSON**을 가져와 검사했다. 라커룸 합계·통산 통합/클럽/국대·대회 필터·경기 상세의 값이 원본과 일치한다. TXT는 생성 함수의 전체 UTF-8 문자열과 같고, JSON 재내보내기에서 **경기 원본 이벤트까지 그대로** 보존한다. 이후 재실행에서도 새 지표와 미집계 구분이 유지된다. 페이지 오류·외부 HTTP 요청은 0건이다. [결과](validation/release-2.10.0/records-ui.json) · [12시즌 기록](validation/release-2.10.0/records-long.png) · [모바일 혼합 기록](validation/release-2.10.0/records-mixed-mobile.png) · [CB 은퇴 TXT](validation/release-2.10.0/retirement-CB.txt) · [GK 은퇴 TXT](validation/release-2.10.0/retirement-GK.txt)

이 환경은 Linux Chromium으로 같은 다운로드용 HTML을 HTTP로 전달해 검증했다. Windows Edge에서 `file://`로 직접 실행한 측정은 아니다. 파일 안에 게임·명단·폰트·913개 배지와 Blob Worker를 포함하고 외부 자산 요청 없이 검사했다. [종합 결과](validation/release-2.10.0/summary.json)

## 다운로드

검수한 HTML과 ZIP을 공개한 뒤 내려받기 주소와 SHA-256 확인 결과를 기록한다.

기존 파일에서 JSON 내보내기 → 새 ZIP 압축 해제 → `Kball.html`에서 JSON 불러오기 순서로 이어 한다. 하단 **K볼 2.10.0**을 확인한다. 신규 지표는 새로 치르는 경기부터 집계하며 과거에 없던 기록을 만들어 넣지 않는다.
