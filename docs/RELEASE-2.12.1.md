# K볼 2.12.1 · 전체 능력치 가중치와 장기 진행 성능

## 확인한 문제와 전체 가중치 수정

기존 포처의 체력 비중은 1.677%였다. 체력을 50 올려도 반올림 전 OVR은 0.839만 올랐다. 16개 포지션·160개 유형의 **3,850개 항목 중 2,397개**가 같은 문제가 있었으며 특정 체력 항목에 국한되지 않았다. 기본 비중 0.65에 핵심 순서·유형 가점을 더하는 구조에서 비중 차이가 약 9배까지 벌어졌다.

필드 선수는 **공통 역량 70% + 기존 포지션/유형 평가 30%**로 비중을 구성했다. 공통 역량 안에서도 체력·속도·근력·컨트롤·판단 등 실제 축구의 기초를 반영하며, 역할별 핵심 우선순위는 남긴다. 모든 비중의 합은 100%다. 새 필드 비중은 **약 3.10~8.96%**, 한 유형 안의 격차는 최대 약 2.9배다. 골키퍼는 전용 10개 항목에 공통 35%·유형 65%를 적용해 낮은 항목의 비중도 높였다.

| 포처의 능력치 | 기존 비중 | 새 비중 | 50 상승 시 반올림 전 OVR 기여: 기존→신규 |
|---|---:|---:|---:|
| 체력 | 1.68% | 5.05% | +0.84 → +2.53 |
| 근력·속도 | 1.68% | 3.65% | +0.84 → +1.83 |
| 패스·드리블 등 최저 비중 항목 | 1.68% | 3.10% | +0.84 → +1.55 |

표는 다른 조건이 같고 실제로 50을 올렸을 때의 기초 평가 비중이다. 정수 OVR의 변화량은 시작 소수부와 반올림에 따라 달라진다. 50으로 균일한 통제 선수에서 어느 필드 항목을 50 올려도 표시 OVR이 최소 2 오르는지 전수 검사했고, 포처 체력은 3 올랐다. 실제 2.12.0 중도 저장을 PC/모바일로 가져온 별도 사례에서는 체력 66→116으로 표시 OVR이 2 올랐다. 원래의 50 상승→약 0.84인 반영을 고친 것이며 모든 항목이 같은 비중이 되는 방식은 아니다.

화살표는 바뀐 실제 비중의 순서를 따르고, 툴팁에 **비중과 해당 능력치 +10의 기초 OVR 기여**를 함께 보여준다. 좁은 PC 화면에서도 긴 이름이 낱글자로 끊기지 않게 조정했다. 원능력치 상한 120, 실제 숙련 최대 10, 최대 5개 스킬, 선택만으로 점수가 오르지 않는 규칙과 OVR 130은 유지한다. 균일한 50/75/90/100/110/120 능력은 포지션과 구단에 관계없이 같은 점수다.

## 기존 저장과 성장 기록

2.12.0 및 그 이전 산식을 별도로 보존해 **원본 체크섬을 먼저 검증**한다. 현역 저장의 현재 OVR을 한 번만 재평가하고, 원능력치·숙련·잠금·훈련 선택·기존 경기·개인/팀 수상·체결 계약·과거 몸값은 유지한다. 도입 연도/라운드/전후 점수를 저장한다. 이미 은퇴한 저장은 당시 점수로 보존한다.

산식 전환을 능력치 성장으로 취급하지 않으며 선수 요약과 새 성장 리포트의 증감에서 구분한다. 과거 완료 시즌의 점수를 소급 수정하지 않고 해당 연도 TXT에 개편을 명시한다. 이 차이를 지속적인 기량 하락으로 오인해 계약/몸값에 불이익을 주지 않도록 과거 평가의 척도도 비교한다. 실제 능력치가 여러 시즌 하락한 경우의 주급/몸값 조정은 기존대로 작동한다.

## 진행 지연의 원인과 수정

실제 14시즌 파일에서 경기 계산과 Worker 전달·자동 저장을 분리해 측정했다. 경기마다 서로 다른 로스터 객체를 펼쳐 새 선수 객체를 만들고, 변경되지 않은 수백 MB의 과거 기록을 Worker에서 다시 복사하는 비용이 컸다. 자동 저장의 정렬/체크섬·JSON 생성도 전체 대기를 차지했다.

- 경기 선수와 통계 객체의 형태를 일정하게 만들어 반복 복사와 GC 비용을 줄였다. 빈 유형의 정규식 검사도 반복하지 않는다. 모든 행동·확률 추첨·상대·일정·경합·수비/공격 계산을 실행한다.
- Worker는 변경되지 않은 시즌/경기/국대/대회 원장에 대해 기준 저장 ID·리비전과 참조를 보내고, 화면의 원본으로 복원한다. 신규 경기와 변경된 데이터는 전부 보낸다. 이를 저장 파일의 생략으로 사용하지 않으며 **복원 후 기존 전체 검증·체크섬·완전한 저장**을 유지한다. 장기 커리어에서 유휴 Worker를 종료하는 기존 메모리 정책도 유지한다.
- 체크섬과 JSON의 반복 키/구두점·숫자 토큰 생성을 줄였다. 모든 필드와 과거 기록을 계속 방문하고 검증하며, 구형 체크섬 바이트와 JSON 내용이 동일하다. 버퍼의 메모리 제한도 유지한다.

성능 수정만 분리한 동결 산식에서 8라운드·3,396경기를 전부 계산한 3회 교대 측정 중앙값은 **5.99초→3.97초(약 34% 단축)**다. 여섯 결과의 전체 커리어 SHA-256이 모두 같아 점수뿐 아니라 기록 전체가 일치한다. [반복 실험](validation/release-2.12.1/world-performance.json), [분리한 수정](validation/release-2.12.1/performance-only.patch).

실제 14시즌 파일의 Worker 반환 데이터는 **272,712,996→45,684,864바이트(약 83% 감소)**였다. 복원 후 전체 커리어 해시는 일반 반환 방식과 같았다. 기록은 모두 남으며 중복 복사만 줄인다. [복원·전송 검증](validation/release-2.12.1/transport-performance.json).

같은 14시즌 파일을 사용하는 독립 HTML의 실제 클릭부터 자동 저장 완료까지의 별도 측정:

| 동작 | 2.12.0 | 2.12.1 |
|---|---:|---:|
| 가져오기·저장 | 49.5초 | 24.8초 |
| 이적 계약 | 54.6초 | 20.9초 |
| 다음 시즌 시작 | 27.6초 | 13.6초 |
| 전반기·자동 저장 | 48.3초 | 29.9초 |

공유 클라우드의 Linux Chromium에서 동일 HTML을 localhost로 실행한 단일 저장 사례다. 실제 Windows Edge의 직접 file:// 성능 보장값과 구분하며 시점별 부하 차이도 있다. 별도의 교대 CPU 실험과 전체 결과 일치 검증을 함께 제공한다. [클릭 측정 전](validation/release-2.12.1/browser-before.json), [후](validation/release-2.12.1/browser-after.json).
