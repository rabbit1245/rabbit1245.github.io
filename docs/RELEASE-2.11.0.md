# K볼 2.11.0 · 유니폼 판매·저장 복구·몸값과 주급

## 유니폼 판매 시장

게임에 보존된 **913개 구단과 실제/가상 선수단 전체**를 대상으로 유한한 유니폼 시장을 만들었다. 실존 구단·선수별 비공개 실제 판매량을 확보한 시스템은 아니다. 판매량과 순위는 **게임 내 시장 결과**이며 공개된 실제 판매 순위로 표현하지 않는다. 기존 2024/FC25 선수 명단도 유지한다.

- 구단별 팬 기반과 브랜드 차이를 두고 같은 구단 선수들이 이름 유니폼 판매 비중을 나눈다. 세계 총수요와 구단·개인 판매량이 정수로 정확히 합산된다. 무지·레트로 등은 별도 20%로 구분해 현역 선수 판매에 중복 배정하지 않는다.
- 개인 실적·출전량·포지션별 기여·실제 기량·스타성·게임 내 누적 명성, 클럽의 리그/컵 성적과 인기도를 반영한다. 공격수의 득점만 평가하지 않고 미드필더/수비수/GK의 기여도 구분한다. 유명 NPC의 초기 인지도는 보존된 실존 선수에게만 적용하며 사용자가 유명인 이름을 입력해 명성을 얻을 수는 없다.
- 클럽의 실제 순위·우승·전력 상승이 이후 인기도에 점진적으로 반영된다. 인기와 명성은 다음 시즌으로 이어지고 과거 확정 판매량은 바꾸지 않는다. 시장 계산은 시즌 결산 때 한 번 수행하며 훈련·성향 클릭에는 추가하지 않는다.
- 기존 커리어는 보존된 세계 수상/순위·최근 실제 성적과 구단 성과 재투자를 초기 명성/인기도에 반영한다. 이미 유명한 선수와 성장시킨 클럽을 새로 생긴 무명 선수/구단으로 취급하지 않으며, 과거 판매량을 만들어 넣지는 않는다.
- 시즌 성적에서 내 판매량, 세계 순위, 구단 내 순위, 소속팀별 판매량과 인기도 변화, 세계 상위 20명을 볼 수 있다. 이적했다면 두 소속팀 판매량을 구분하고 개인 세계 순위에서는 합산한다. 시즌 전체 FA는 클럽 유니폼 0장으로 기록한다.
- 완료 시즌의 세계 **1·2·3위는 `K볼 유니폼 판매 N위` 개인상**을 받는다. 시즌 도중 은퇴한 경우 그 시점까지의 부분 집계를 남기되 연간 개인상을 확정하지 않는다. 과거 `구단 유니폼 판매 예상 1위`는 보존하고 앞으로는 판매량 없는 예상 순위 상을 새로 만들지 않는다.
- 시즌 이력·수상 화면·연도별 은퇴 TXT·JSON/자동 저장을 연결했다. 도입 이전 완료 시즌은 미집계이며 0장으로 소급 생성하지 않는다. 판매량을 선수 급여나 이적료에 자동 합산하지 않는다.

팬 기반, 이름 유니폼 비율, 개인 인지도 가중치와 시장의 연 1.2% 증가 등은 게임 보정값이다. 집계 경계는 게임의 논리 시즌이다. 명성은 현재 성적만으로 급변하지 않고, 부상이나 부진 중에도 기존 팬 수요가 남는다. 세계 상위권은 다른 모든 선수와 경쟁하므로 스타성 10만으로 판매 메달을 보장하지 않는다.

## 실제로 재현한 저장 오류

2.10.2에서 상대 팀 GK 전원이 부상인 상황과 사용자 GK 퇴장 상황을 각각 재현했다. 동일한 오류가 발생했다.

> 저장 데이터 오류: 신규 행동 원장 · 크로스 상대 골키퍼

선수 수만 확인해 명단을 채우다 GK가 빠지거나, GK 퇴장 후 교체 GK까지 지워진 상태에서 엔진이 첫 번째 필드 선수를 골키퍼로 사용했다. 크로스 원장에는 그 선수 ID가 GK로 기록되지만 경기 명단에는 RB/CB 등 원래 포지션이 남아 저장 검증과 충돌했다. 이는 SVG 로고 데이터 오류가 아니다.

수정한 경로는 다음과 같다.

1. GK/필드 선수를 구분해 선발하며, 건강한 GK와 필요한 벤치 인원이 부족하면 기존에 지원하던 명시적 `(가상)` 예비 선수를 편성한다. 필드 선수를 넣다가 GK를 밀어내는 경로도 막았다.
2. 사용자 GK가 퇴장하면 필드 선수 한 명을 빼고 예비 GK를 투입해 **10명과 GK 1명**을 유지한다. 부상 교체와 퇴장은 구분한다.
3. 새 경기에는 명단 버전을 남기고 실제 명단이 보존된 경기의 GK 출전 구간에 공백/중복이 없는지 검사한다. 압축된 NPC 국대 기록처럼 원래 명단이 없는 자료에 명단을 만들어 넣지는 않는다.
4. 기존 오류 경기에서는 원본 크로스·선방·출전 구간으로 확인되는 긴급 GK 역할만 주석으로 복구한다. 선수의 등록 포지션·이벤트·득실점·개인 기록을 변경하지 않는다. 파일은 **먼저 원래 체크섬을 검증**하며, 조작된 파일이나 새 엔진의 잘못된 명단을 이 복구로 통과시키지 않는다. 자동 저장·이전 Blob 저장·JSON 가져오기/내보내기를 모두 연결했다.

별도로 2.10.2에서 실제 한 라운드를 진행해 만든 오류 파일을 가져오고 재저장·재실행했다. 원본 이벤트와 개인 기록이 같았다. [재현/복구](validation/release-2.11.0/recovery.json)

## 저장 메모리와 실행 검수

저장 Worker는 이미 별도 사본을 받는데 그 안에서 다시 전체 JSON 직렬화→파싱으로 큰 사본을 만들고 있었다. Worker가 소유한 사본에서는 그 복제만 제거했다. **전체 검증·모든 기록·기존 정규 체크섬은 유지**하며 외부 호출의 기본 격리 사본도 유지한다. 큰 자료의 검사 타임아웃은 구분한다.

JSON 다운로드도 메인 화면에서 전체 커리어를 또 복제/문자열화하던 경로를 바꿔, Worker가 검증한 Blob을 직접 내려준다. 검사에 실패한 데이터를 정상 파일로 내보내거나 오류 기록을 삭제하는 방식은 사용하지 않는다.

실제 세계 전체 **5시즌을 Node에서 진행한 후 그 저장으로 Chromium에서 3시즌을 추가 진행**했다. 각 반 시즌 진행과 시즌 경계, 자동 저장, 재실행, 약 178MB JSON 내보내기, 은퇴와 한국어 TXT를 확인했다. 진행 중 오류·페이지 종료는 없었다.

| 추가 진행 시즌 | OVR | 판매량 | 페이지 JS 힙 사용량 |
|---|---:|---:|---:|
| 2031 | 90 | 209,325장 | 약 510MB |
| 2032 | 90 | 230,024장 | 약 609MB |
| 2033 | 90 | 221,999장 | 약 706MB |

8시즌 종료 파일은 **177,500,585바이트**다. 초기 5시즌의 기존 경기·스탯·수상·몸값·판매량을 대조했고, 기존 설계대로 다음 시즌 경계에 추가되는 직전 시즌 구단 재투자 보고서만 별도로 구분했다. 통산 합계와 은퇴 TXT를 다시 계산해 비교했으며 능력치는 모두 90으로 유지됐다. 클럽 인기도는 도입 기준 100에서 약 162로 성장했다. [브라우저 진행](validation/release-2.11.0/long-browser.json) · [원본/출력 대조](validation/release-2.11.0/eight-seasons.json)

이는 Linux Chromium 검수다. 사용자가 실행한 Edge의 실제 저장 파일은 제공되지 않았으므로 사용자의 종료 원인을 하나로 단정하거나 무제한 시즌의 메모리를 보장하지 않는다. 과거 기록을 보존하므로 데이터 크기는 계속 증가한다. 이미 브라우저가 종료되어 저장되지 않은 진행을 새로 복원하는 기능은 아니다.

## 수상 기준 접기

모든 개인상은 이름을 누르면 수상 기준·선정 결과·주최 정보를 펼친다. 기본 상태에서는 설명이 숨겨지고, 접기/펼치기는 경기 계산이나 저장 명령을 호출하지 않는다. 기존 팀 우승·수상 목록·세계 수상 결과 화면은 보존한다. 새 판매 개인상도 같은 방식이다.

## 몸값·주급

원래 몸값은 OVR의 영향이 크고, 어린 선수의 충분한 돌파 시즌도 작은 per90 보너스에 걸려 덜 뛰어난 시즌과 차이가 작았다. 잠재력, 실제 출전 시간과 경기 수, 성적의 양, 리그 수준을 반영해 어린 선수의 검증된 돌파 시즌 프리미엄을 보완했다. 표시 OVR 100 초과의 숙련 보정을 그대로 가격에 거듭 확대하지 않고 실제 기량을 사용한다.

같은 **능력치 80·잠재력 95·기본 스타성·소시에다드·라리가 15골/10도움·34경기/2,700분·평점 7.5** 조건의 통제 평가다. 실제 시즌 플레이나 사용자의 세이브 재현과 구별한다.

| 나이 | 새 평가액 | 고정 환율 표시 |
|---|---:|---:|
| 18세 | €89,776,000 | 약 1,347억 원 |
| 19세 | €79,215,000 | 약 1,188억 원 |

소수 경기의 반짝 성적으로 같은 프리미엄을 얻지 않도록 출전과 누적 실적을 함께 확인한다. 모든 18~19세에게 일정 몸값을 보장하는 규칙은 아니다. 시장가치와 구단 간 실제 입찰 이적료도 구분한다.

새 계약의 주급 환산은 기존 `몸값 / (52×210)` 대신 현대적인 연봉/가치 비율과 나이·역할·폼·구단 예산을 반영한다. 해당 계수는 기존 코드에서 특히 낮았다. **이미 체결한 계약 주급, 과거 시장가치·급여·이적료는 고치지 않는다.** 이전 가격 기준의 미확정 제안은 한 번 갱신하며 기존 고능력 베테랑의 기량 중심 계약 기간과 정상 재계약 경로를 유지한다.

주요 20개 구단의 수입 규모는 [Deloitte Football Money League 2026](https://www.deloitte.com/uk/en/services/financial-advisory/analysis/deloitte-football-money-league.html)의 2024/25 매출을 기준점으로 사용한다. 기존의 획일적인 전력 기반 수입만으로 주요 팀의 입찰·급여 예산이 지나치게 작던 부분을 보완했다. 이전에 벌어둔 자금은 줄이지 않으며 구단 전력을 임의로 올리는 보정은 넣지 않았다. 매출 기준과 유니폼 판매량의 게임 가정은 구분한다. 기존 유로 저장과 **1유로=1,500원** 표시 환율도 유지한다.

## 성능 비교

다른 검사가 끝난 동일 기계에서 2.10.2와 최종 소스를 번갈아 비교했다. Linux Node 20 측정이며 Edge의 프로세스 메모리나 클릭 시간을 직접 측정한 값은 아니다.

- 실제 5시즌 **122MB 저장**, 각각 별도 프로세스에서 동일한 Worker 소유 입력·전체 검증·정규 체크섬을 수행한 3회 비교: 중앙 최대 RSS **약 1,126→843MB, 약 25% 감소**, 처리 시간 **5.54→4.08초, 약 26% 단축**. 여섯 실행의 전체 체크섬이 같았다.
- 원본을 보존하는 경기 1,000회·5회 중앙값: **917.34→914.68ms**, 약 -0.3%.
- 집계 뒤 버리는 NPC 경기 1,000회: **804.47→863.78ms**, 약 +7.4%. 합법적인 GK/필드 선발 조건의 비용은 남는다.
- 세계 전체/커리어 2라운드·3회 중앙값: **1014.27→1058.90ms**, 약 +4.4%·약 45ms. 양쪽 모두 리그 726경기를 계산했다.

경기 계산·원본·세부 기능을 생략해 속도를 낸 변경은 없다. [저장 메모리/시간](validation/release-2.11.0/save-memory.json) · [순수 경기](validation/release-2.11.0/engine-performance.json) · [세계 진행](validation/release-2.11.0/world-performance.json)
